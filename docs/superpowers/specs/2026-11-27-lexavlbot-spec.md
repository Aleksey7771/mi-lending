## 1. Executive Summary

@lexavlbot — персональный AI-ассистент для одного человека: владельца оптовой торговли морепродуктами (красная икра, краб, рыба с Дальнего Востока). Бот берёт на себя 2–3 часа ежедневной рутины: создание постов, коммерческих предложений, управление прайсом и ответы клиентам в Max.

Пользователь отправляет фото + короткую команду в Telegram → AI готовит контент → пользователь одобряет → бот публикует. Никакой автономной публикации.

## 2. Problem Statement

### Текущая боль
Владелец работает один и ежедневно тратит 2–3 часа на:
- Написание постов с фото товара для Max и Telegram-канала
- Составление и отправку коммерческих предложений (PDF с логотипом)
- Рассылку актуального прайса
- Ответы на типовые вопросы клиентов (цены, наличие, доставка)

### Почему сейчас
Ниша красной икры и краба в Telegram атакована мошенниками (30+ фейковых каналов, данные Роскачества 2025–2026). Легальный продавец с автоматизированным, но профессиональным присутствием получает конкурентное преимущество.

### Метрики успеха
- Время на создание одного поста: с 20 минут → до 2 минут
- Время на составление КП: с 30 минут → до 3 минут
- Время первого ответа клиенту в Max: с часов → до 30 секунд (круглосуточно)

## 5. Функциональные требования

### 5.1 Управление ботом (Telegram-интерфейс)

**P0 — Обязательно:**
- Пользователь отправляет фото + текст → бот генерирует контент
- Пользователь пишет текст без фото → бот использует фото из каталога
- Бот показывает превью: текст + кнопки [✅ Опубликовать] [🔄 Переписать] [✏️ Исправить] [❌ Отмена]
- Команда /catalog — управление каталогом
- Команда /price — сформировать и отправить прайс
- Команда /kp — создать коммерческое предложение

**P1 — Важно:**
- /style — показать примеры стилей и выбрать
- /feedback — оценить последний пост (учится на оценке)
- /stats — сколько постов создано, сколько КП отправлено

### 5.2 Каталог товаров

**Структура позиции:**
```
- name: string              # "Икра горбуши"
- category: enum            # икра / рыба / морепродукты / другое
- form: string              # "солёная", "б/г", "филе", "тушка"
- unit: string              # "кг", "блок (22 кг)", "ящик"
- price_retail: float       # розничная цена ₽/ед
- price_wholesale: float    # оптовая цена ₽/ед
- price_vip: float | null   # индивидуальная (не показывается публично)
- min_order_wholesale: int  # минимальная партия для опта (кг/ед)
- volume_tiers: JSON        # {"5": 2900, "10": 2700} — скидки от объёма
- origin: string            # "Камчатка", "Сахалин", "Приморье"
- description: text         # для генерации постов
- photo_file_id: string     # Telegram file_id последнего фото
- in_stock: bool            # есть в наличии
- seasonal_note: string     # примечание о сезонности
- created_at: datetime
- updated_at: datetime
```

**Команды управления каталогом (свободный текст):**
- "добавь товар: икра горбуши, 450₽ опт, 580₽ розница, от 5 кг опт"
- "обнови цену на горбушу: 465₽"
- "горбуша закончилась" / "горбуша есть"
- "покажи каталог" → таблица с кнопками редактирования

### 5.3 Генерация контента

**Типы контента:**

| Тип | Описание | Платформа | Формат |
|-----|---------|-----------|--------|
| Пост анонс | Новый товар или поступление | Max + Telegram | Текст + фото |
| Акционный пост | Скидка, распродажа | Max + Telegram | Текст + фото |
| Прайс-пост | Список актуальных цен | Max + Telegram | Текст (таблица) |
| КП | Коммерческое предложение | Max / пересылка | PDF-файл |
| Ответ клиенту | Диалог в Max | Max | Текст |

**Правила генерации (КРИТИЧНО — нарушение недопустимо):**
1. Цены — ТОЛЬКО из каталога. Никогда из головы AI.
2. Наличие — ТОЛЬКО из поля `in_stock`. AI не предполагает.
3. Если товара нет в каталоге — сообщает пользователю, не генерирует пост.
4. Индивидуальные цены (`price_vip`) — не показываются публично никогда.

**Шаблон поста (базовый, до обучения стилю):**
```
[эмодзи категории] [НАЗВАНИЕ ТОВАРА] | [ФОРМА]

📍 Происхождение: [origin]
📦 [Характеристика: вес блока, форма упаковки]
✅ В наличии

💰 Розница: от [price_retail] ₽/кг
📊 Опт от [min_order_wholesale] кг: от [price_wholesale] ₽/кг

[2–3 предложения из description — о вкусе, качестве, особенностях]

👉 Заказать / уточнить: @[manager_contact]
```

**Формат КП (PDF):**
- Шапка: логотип + название компании + контакты
- Дата актуальности
- Таблица: позиция / форма / происхождение / цена опт / мин. партия
- Условия доставки (берётся из настроек)
- Реквизиты (ИП/ООО когда будет, пока placeholder)
- Генерируется через `fish-agent/pdf/generator.py` (адаптированный)

### 5.4 Публикация

**Платформы v1:**

| Платформа | Механизм | Бот |
|-----------|---------|-----|
| Max (контент) | Max Bot API | @lexav_post_bot |
| Telegram-канал | Telegram Bot API, бот = admin | @lexavlbot как admin |
| Max (клиенты) | Max Bot API, входящие | @lexav_chat_bot |

**Маршрутизация команды "разошли в Max и в Telegram":**
- Пользователь говорит куда в команде
- Бот публикует в оба места, сообщает: "✅ Опубликовано в Max и Telegram-канале"

### 5.5 Ответы клиентам в Max

**Логика диалога:**
```
Клиент → @lexav_chat_bot (Max)
         ↓
    Определение типа запроса:
    
    Запрос цены/наличия → ответ из каталога
    Запрос доставки → ответ из настроек
    Вопрос о сертификатах → стандартный ответ + предложение запросить
    Просьба об индивидуальной цене → общая цена + "уточните у менеджера @manager"
    Нестандартный вопрос → "уточню у менеджера, отвечу в течение [время]" + уведомление владельцу
    
         ↓
    Владелец получает уведомление в Telegram:
    "[Новый диалог в Max] Клиент: [имя]
     Вопрос: [текст]
     Ответ бота: [текст]
     [Переписать ответ] [Всё верно]"
```

**Ограничения AI-ответов:**
- Никогда не называет цену выше/ниже чем в каталоге
- Никогда не обещает доставку в срок, которого нет в настройках
- Никогда не говорит "скидка" без команды владельца
- При любом сомнении → "уточню и отвечу" + уведомление владельцу

### 5.6 Обучение стилю

**Механизм (3 фазы):**

**Фаза 1 — Калибровка при старте:**
1. При первом запуске бот показывает 3 варианта одного и того же поста в разных стилях:
   - Деловой: факты без воды
   - Личный: от лица автора, с историей
   - Смешанный: факты + короткая эмоция
2. Пользователь выбирает ближайший
3. Уточняет: использовать эмодзи (да/нет/немного)

**Фаза 2 — Обратная связь на каждый пост:**
После публикации:
```
Бот: "Пост опубликован. Как вышло?
     👍 Хорошо  |  ✏️ Слишком [длинно/коротко/формально/неформально]"
```
Оценки сохраняются в `style_feedback` таблицу.

**Фаза 3 — Обучение на накопленных данных:**
После 10+ оценок бот перестраивает промпт: добавляет/убирает характеристики стиля.
Хранится в таблице `style_profile`:
```json
{
  "length": "medium",        // short / medium / long
  "emoji_density": "low",    // none / low / medium / high
  "tone": "professional",    // casual / professional / mixed
  "cta_style": "soft",       // hard ("Заказывайте!") / soft ("Уточнить у менеджера")
  "origin_mention": true,    // всегда упоминать регион
  "price_in_post": true,     // указывать цену в посте
  "sample_good": ["..."],    // примеры одобренных постов (до 5)
  "sample_bad": ["..."]      // примеры отклонённых постов (до 5)
}
```

### 6.3 База данных

```sql
-- Каталог товаров
CREATE TABLE products (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    category TEXT CHECK(category IN ('икра','рыба','морепродукты','другое')),
    form TEXT,
    unit TEXT DEFAULT 'кг',
    price_retail REAL,
    price_wholesale REAL,
    price_vip REAL,
    min_order_wholesale INTEGER DEFAULT 1,
    volume_tiers TEXT,          -- JSON: {"5": 2700, "10": 2500}
    origin TEXT,
    description TEXT,
    photo_file_id TEXT,
    in_stock BOOLEAN DEFAULT 1,
    seasonal_note TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Настройки доставки и компании
CREATE TABLE settings (
    key TEXT PRIMARY KEY,
    value TEXT
    -- Ключи: delivery_zones, delivery_min_order, company_name,
    --        manager_contact, company_inn, company_legal (когда будет),
    --        certifications_note
);

-- Профиль стиля
CREATE TABLE style_profile (
    id INTEGER PRIMARY KEY,
    profile_json TEXT,          -- JSON с параметрами стиля
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- Обратная связь по стилю
CREATE TABLE style_feedback (
    id INTEGER PRIMARY KEY,
    post_text TEXT,
    post_type TEXT,             -- 'post', 'kp', 'price'
    rating TEXT,                -- 'good', 'too_long', 'too_formal' и т.д.
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- История диалогов клиентов (Max)
CREATE TABLE client_dialogs (
    id INTEGER PRIMARY KEY,
    platform TEXT DEFAULT 'max',
    client_id TEXT,
    client_name TEXT,
    message TEXT,
    bot_response TEXT,
    escalated BOOLEAN DEFAULT 0,  -- передан ли менеджеру
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 6.4 Переменные окружения (.env)

```env
# Безопасность
ALLOWED_USER_ID=123456789          # Telegram ID владельца

# Telegram
TELEGRAM_BOT_TOKEN=...             # @lexavlbot
TELEGRAM_CHANNEL_ID=@channel_name  # существующий канал

# Max
MAX_CONTENT_BOT_TOKEN=...          # @lexav_post_bot
MAX_CONTENT_CHANNEL_ID=...         # ID канала в Max
MAX_DIALOG_BOT_TOKEN=...           # @lexav_chat_bot

# AI (OpenRouter)
OPENROUTER_API_KEY=...
CONTENT_MODEL=deepseek/deepseek-chat
DIALOG_MODEL=anthropic/claude-haiku-5-5
ROUTER_MODEL=anthropic/claude-haiku-5-5

# Настройки
MANAGER_CONTACT=@manager_username  # куда направлять клиентов
RESPONSE_TIME_HOURS=2              # обещанное время ответа менеджера
```

### 6.5 Безопасность

- Бот принимает команды ТОЛЬКО от `ALLOWED_USER_ID`. Все остальные сообщения молча игнорируются.
- Max dialog-бот принимает сообщения от любых клиентов, но не раскрывает VIP-цены и не выполняет административных команд.
- Токены только в `.env`, не в коде.
- SQLite-база не открыта для внешних подключений.

## 8. Сценарии использования (детальные)

```

5. Бот → владелец:
   ─────────────────
   📸 [превью поста]
   ─────────────────
   Куда публиковать: Max + Telegram-канал
   
   [✅ Опубликовать] [🔄 Переписать] [✏️ Исправить] [❌ Отмена]
6. Владелец: [✅ Опубликовать]
7. Бот публикует в Max и Telegram-канал

9. Оценка сохраняется в style_feedback
```

### Сценарий 2 — Прайс с проверкой цен

```
1. Владелец: "отправь прайс в Max"
2. Система: формирует список всех in_stock=true товаров
3. Бот → владелец: показывает таблицу цен (все позиции)
4. Бот: "Цены актуальны? Публикуем?"
```

## 9. Нефункциональные требования

### Производительность
- Генерация поста: не более 10 секунд (показывать "⏳ Генерирую..." сразу)
- Ответ клиенту в Max: не более 5 секунд
- Определение намерения: не более 2 секунд

### Надёжность
- При ошибке OpenRouter: повторить 2 раза, потом уведомить владельца
- При ошибке Max API: уведомить владельца с текстом поста для ручной публикации
- Лог ошибок в файл (не теряем данные о попытках публикации)

### Мониторинг
- Telegram-уведомление владельцу при критических ошибках
- Еженедельная сводка: сколько постов создано, КП отправлено, диалогов обработано

## 10. Доверие и юридические требования

### Обязательные элементы в каждом посте
Так как ниша атакована мошенниками (30+ фейковых каналов), бот добавляет в каждый пост или в шапку канала:
- Регион происхождения товара (обязательно)
- Контакт менеджера (не анонимный)

### В PDF-КП (обязательно)
- Placeholder для ИП/ООО (сейчас пустой, заполнится когда будет юрлицо)
- Телефон/мессенджер контактного лица
- Дата актуальности прайса

### Когда появится ИП/ООО
- В `settings` добавляется `company_legal`, `company_inn`
- Все PDF автоматически начинают включать реквизиты
- В описание Max-канала добавляется ИНН
