# Техническая спецификация: Fish Price Agent

**Дата:** 11.11.2026 (обновлено 12.11.2026)  
**Версия:** 1.1  
**Статус:** Готово к разработке  

---

## 1. Executive Summary

Персональный AI-агент для владельца оптовой торговли рыбой и морепродуктами с Дальнего Востока. Работает через Telegram-бот, автоматизирует рутинные задачи, которые сейчас занимают 2–3 часа в день. Агент имеет долгосрочную память (клиенты, поставщики, цены, предпочтения), умеет генерировать PDF-прайс, писать посты в стиле владельца и рассылать сводки.

**Единственный пользователь:** владелец бизнеса.  
**Основной интерфейс:** Telegram-бот.  
**Fine-tuning модели не используется:** обучение = few-shot промпты + итеративный фидбек + PostgreSQL-память.

## 2. Проблема и цели

### Текущая боль

| Задача | Время сейчас |
|--------|-------------|
| Мониторинг цен (обзвон, прайсы) | 60–90 мин/день |
| Рассылка прайса по Telegram/WhatsApp/email | 30–40 мин/день |
| Генерация PDF КП | 20–30 мин/раз |
| Контент для соцсетей | 20–30 мин/пост |

### Критерии успеха MVP

- [ ] Утренняя сводка готова к 09:00 по Владивостоку (Asia/Vladivostok, UTC+10) — владелец приезжает, открывает бот, видит актуальную картину
- [ ] Команда `/preis` выдаёт PDF через ≤10 сек
- [ ] Обновление цены через текст за ≤30 сек (написал → подтверждено → сохранено)
- [ ] КП для клиента генерируется за ≤15 сек по команде
- [ ] Парсеры fishnet.ru + fishretail.ru + fishery.ru обновляют базу каждый час без ошибок
- [ ] Если бот/сервер упал — владелец получает уведомление в Telegram

## 3. Архитектура системы

### 3.1 Структура агента

```
Источники данных (фоновые процессы)
    ├── WebParser     — fishnet.ru, fishretail.ru, fishery.ru (каждый час)
    ├── TgReader      — личные сообщения Telegram владельца (Telethon, V1.5)
    └── MaxReader     — личные сообщения Max (max.ru) владельца (V1.5)
              ↓ все пишут в PostgreSQL
Владелец (Telegram-бот) 
    ↓ текст/команда
Оркестратор (Claude Sonnet)
    ↓ определяет задачу
    ├── PriceAgent    — работа с ценами, сводки, сравнения
    ├── ContentAgent  — генерация постов и КП
    ├── PDFAgent      — сборка PDF-прайса и КП
    ├── OutreachAgent — подготовка рассылок (email / Telegram / WhatsApp)
    └── MemoryAgent   — чтение/запись долгосрочной памяти
```

### 3.2 Три слоя памяти

| Слой | Хранит | Технология | TTL |

| Краткосрочная | Контекст диалога (FSM-состояния) | aiogram FSM (Redis) | Сессия |

## 4. Схема базы данных

### 4.1 Таблица `products` (каталог позиций)

```sql
CREATE TABLE products (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(100) NOT NULL UNIQUE,  -- "треска б/г"
    aliases     JSONB DEFAULT '[]',             -- ["треска без головы", "ТРЕСКА БГ"]
    category    VARCHAR(50),                    -- "белая рыба", "красная рыба", "морепродукты"
    unit        VARCHAR(10) DEFAULT 'кг',
    season_note VARCHAR(200),                   -- "горбуша: июль–сентябрь"
    is_active   BOOLEAN DEFAULT true,
    created_at  TIMESTAMP DEFAULT NOW()
);

-- Индексы
CREATE INDEX idx_products_category ON products(category);
```

**Начальный список категорий:** белая рыба, красная рыба, морепродукты, икра, пресервы.

### 4.2 Таблица `suppliers` (поставщики)

```sql
CREATE TABLE suppliers (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,
    telegram    VARCHAR(100),
    phone       VARCHAR(20),
    email       VARCHAR(100),
    region      VARCHAR(100),  -- "Сахалин", "Камчатка", "Владивосток"
    is_active   BOOLEAN DEFAULT true,
    notes       TEXT,
    created_at  TIMESTAMP DEFAULT NOW()
);
```

### 4.3 Таблица `clients` (клиенты)

```sql
CREATE TABLE clients (
    id              SERIAL PRIMARY KEY,
    name            VARCHAR(100) NOT NULL,
    type            VARCHAR(50),    -- "ресторан", "магазин", "оптовик", "физлицо"
    telegram        VARCHAR(100),
    phone           VARCHAR(20),
    email           VARCHAR(100),
    city            VARCHAR(100),
    min_order_kg    DECIMAL(8,2),
    discount_pct    DECIMAL(4,2) DEFAULT 0,  -- % скидки от базового прайса
    notes           TEXT,
    is_active       BOOLEAN DEFAULT true,
    created_at      TIMESTAMP DEFAULT NOW()
);
```

### 4.4 Таблица `supplier_prices` (история цен поставщиков)

```sql
CREATE TABLE supplier_prices (
    id          BIGSERIAL PRIMARY KEY,
    supplier_id INT REFERENCES suppliers(id),
    product_id  INT REFERENCES products(id),
    price_rub   DECIMAL(10,2) NOT NULL,
    source      VARCHAR(50),   -- "fishnet", "fishretail", "manual", "email"
    source_url  VARCHAR(500),
    recorded_at TIMESTAMP DEFAULT NOW(),
    valid_until TIMESTAMP,
    raw_name    VARCHAR(200)   -- исходное название у поставщика
);

CREATE INDEX idx_sp_product_time ON supplier_prices(product_id, recorded_at DESC);
CREATE INDEX idx_sp_supplier_time ON supplier_prices(supplier_id, recorded_at DESC);
CREATE INDEX idx_sp_recorded ON supplier_prices(recorded_at DESC);
```

### 4.5 Таблица `my_prices` (мои цены для клиентов)

```sql
CREATE TABLE my_prices (
    id          SERIAL PRIMARY KEY,
    product_id  INT REFERENCES products(id),
    price_rub   DECIMAL(10,2) NOT NULL,
    valid_from  TIMESTAMP DEFAULT NOW(),
    valid_until TIMESTAMP,
    created_at  TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_mp_product ON my_prices(product_id, valid_from DESC);
```

**Логика:** `SELECT * FROM my_prices WHERE product_id=? ORDER BY valid_from DESC LIMIT 1` — берём актуальную.

### 4.6 Таблица `style_examples` (обучение ContentAgent)

```sql
CREATE TABLE style_examples (
    id              SERIAL PRIMARY KEY,
    platform        VARCHAR(20),  -- "telegram", "vk", "ok"
    content         TEXT NOT NULL,
    tags            JSONB DEFAULT '[]',   -- ["лосось", "акция", "опт"]
    is_original     BOOLEAN DEFAULT false, -- true = написано владельцем
    feedback_score  SMALLINT DEFAULT 0,   -- 1 = одобрен, -1 = отклонён, 0 = нейтрально
    generation_params JSONB,              -- параметры запроса при генерации
    created_at      TIMESTAMP DEFAULT NOW()
);
```

### 4.7 Таблица `agent_memory` (ключ-значение для предпочтений)

```sql
CREATE TABLE agent_memory (
    key         VARCHAR(200) PRIMARY KEY,
```

## 6. Промпты агентов (системные инструкции)

### 6.1 Оркестратор

```
Ты — персональный бизнес-ассистент владельца оптовой торговли рыбой и морепродуктами.
Твоя задача: понять намерение пользователя и делегировать нужному специалисту.

КОНТЕКСТ БИЗНЕСА:
- Оптовая торговля свежемороженой рыбой с Дальнего Востока (Сахалин, Камчатка, Приморье)
- Работает один человек, совмещает закупки + продажи + маркетинг
- Регион работы: вся Россия, основные клиенты: рестораны, магазины, оптовики

ВОЗМОЖНЫЕ НАМЕРЕНИЯ:
- update_price: обновить цену поставщика ("треска 180 у Иванова")
- get_preis: получить PDF прайс
- get_kp: сгенерировать КП для клиента
- create_post: написать пост для соцсетей
- price_query: узнать текущую цену по позиции
- add_supplier/client: добавить нового поставщика/клиента
- general_question: другой вопрос

Отвечай только JSON:
{"intent": "<намерение>", "params": {<извлечённые параметры>}, "clarification": "<вопрос если нужен>"}
```

### 6.2 ContentAgent (базовый стиль до накопления примеров)

```
Ты пишешь посты для Telegram-канала оптового торговца рыбой.

ПРАВИЛА СТИЛЯ:
- Деловой и конкретный. Без пафоса и «уникальных предложений».
- Короткие предложения. Максимум 3–5 предложений на пост.
- Всегда конкретные цифры: цена, вес, наличие.
- Используй эмодзи умеренно (1–2 на пост максимум).
- Никаких восклицательных знаков.
- Пиши как предприниматель, а не как маркетолог.

СТРУКТУРА ПОСТА:
1. Что есть (позиция, откуда, форма)
2. Цена и наличие
3. Как взять (условия, контакт)

ПЛАТФОРМА: {platform}
ТЕКУЩАЯ ДАТА: {date}
ПОЗИЦИЯ: {product}
ДАННЫЕ: {price_data}
ДОПОЛНИТЕЛЬНО: {extra}

{style_examples_block}
```

**Блок стилевых примеров** (подставляется динамически из БД):

```
ПРИМЕРЫ ПОСТОВ ВЛАДЕЛЬЦА (учитывай стиль):
---
{example_1}
---
{example_2}
---
```

### 6.3 PriceAgent

```
Ты анализируешь цены на рыбу и морепродукты.

ЗАДАЧА: {task}
ДАННЫЕ ИЗ БД: {price_data}
ТЕКУЩАЯ ДАТА: {date}

При сравнении цен:
- Показывай лучшую цену первой
- Указывай дату последнего обновления цены
- Если данных нет или они старше 48 часов — предупреждай

При утренней сводке:
- Показывай изменения с момента прошлой сводки
- Выделяй рост >5% и снижение >5%
- Давай рекомендацию по своей цене если цена поставщика изменилась
```

### 6.4 MemoryAgent

```
Ты управляешь долгосрочной памятью агента.

ДОСТУПНЫЕ ОПЕРАЦИИ:
- save_supplier: сохранить/обновить поставщика
- save_client: сохранить/обновить клиента  
- save_price: записать цену поставщика
- save_preference: сохранить предпочтение/настройку
- recall: получить информацию из памяти

ПРАВИЛА:
- Перед сохранением нового поставщика/клиента — проверь дубликаты по имени (fuzzy match >85%)
- Всегда подтверждай сохранение пользователю
- При неоднозначности — уточни
```

### Свободный текст

Пользователь может писать свободно — оркестратор разберёт намерение:

```
"Обнови: горбуша 95 рублей, Петров"          → update_price
"Напиши пост про минтай, есть по 68"          → create_post  
"Сделай КП для Марины из Новосибирска"        → get_kp
"Почём треска у всех?"                        → price_query
"Добавь нового поставщика: Сидоров, Камчатка" → add_supplier
```

### Утренняя сводка (автоматическая, 09:00 по Владивостоку)

Владелец приезжает на работу в 9–10 утра, открывает бот — сводка уже готова.

```
📊 Доброе утро. Сводка на 12.11.2026, 09:00

📈 Изменения с вчера:
  Лосось с/м — +8% у Петрова (был 220₽ → 238₽)
  Минтай б/г — −4% у Сидорова (был 72₽ → 69₽)

Лучшие цены сейчас (по каждой позиции):
  Треска б/г      182₽  Иванов       (обновл. 06:15, fishnet)
  Лосось с/м      230₽  Козлов       (обновл. 05:50, личное сообщение)
  Горбуша с/м      95₽  Петров       (обновл. вчера 18:00)
  Минтай б/г       69₽  Сидоров      (обновл. 06:00, fishretail)
  Навага б/г      112₽  нет данных ⚠️
  ...

```

**Инлайн-кнопки:**
- `[Обновить мой прайс]` → по каждой изменившейся позиции: «Поднять треску до 190₽? [Да] [Нет] [Своя цена]»
- `[Скачать PDF]` → генерирует актуальный PDF-прайс и отправляет
- `[Запросить по старым]` → показывает последние известные цены по позициям без данных

## 8. PDF-прайс

### Структура документа

**Шапка:**
- Логотип компании (слева)
- Название компании (по центру)
- «Прайс-лист актуален на: ДД.ММ.ГГГГ» (справа)

**Таблица позиций:**

| Арт. | Наименование | Вид обработки | Цена руб/кг | Наличие |
|------|-------------|--------------|-------------|---------|
| 001 | Треска | б/г | 190 | ✓ |
| 002 | Лосось | с/м | 240 | ✓ |
| ... | | | | |

Колонки группируются по категории (белая рыба / красная рыба / морепродукты).

**Подвал:**
- Условия поставки (из `agent_memory["preis.conditions"]`)
- Контакты: Telegram: @... | Телефон: +7 ...

**Формат:** A4, PDF, генерируется WeasyPrint из HTML-шаблона.

### КП (коммерческое предложение)

Отличается от прайса:
- Адресовано конкретному клиенту (`Уважаемый [Имя]`)
- Цена = `my_prices` × (1 − `clients.discount_pct`)
- Если клиент новый — цена из полного прайса без скидки

### 9.4 Telethon — личные сообщения Telegram (V1.5)

**Что делает:** читает входящие сообщения в личных чатах с поставщиками. Когда поставщик пишет «горбуша 95», агент автоматически извлекает цену.

**Архитектура:**
```
Telethon (отдельный процесс, аккаунт владельца)
    ↓ новое входящее сообщение
LLM-экстрактор: «Найди в тексте позицию и цену. Формат: {product, price, unit}»
    ↓ если нашёл
fuzzy_match → product_id
    ↓
supplier_prices (запись с source="telegram_personal")
    ↓
Уведомление владельцу в бот: «Поставщик Иванов прислал: горбуша 95₽/кг. Сохранить?» [✅] [✏️ Исправить]
```

**Важные условия:**
- Telethon работает от имени личного аккаунта владельца (не бот-аккаунта)
- Требует номер телефона + код подтверждения при первом запуске
- Мониторит только чаты, которые помечены тегом «поставщики» или входят в список `suppliers.telegram`
- Технически: нарушение ToS Telegram, но массово не применяется к личным аккаунтам
- Запускается как отдельный Docker-сервис (`tg_reader`)

**Схема Docker-сервиса:**
```yaml
tg_reader:
  build: ./tg_reader
  restart: always
  env_file: .env
  volumes:
    - ./tg_reader/session:/app/session  # хранит авторизацию
  depends_on:
    - postgres

```

### 9.6 Ручной ввод цены (MVP — основной метод)

Самый надёжный способ в MVP, пока Telethon не подключён.

**3 варианта ввода:**

**А) Свободная фраза:**
```
"Иванов: горбуша 95, минтай 68"
"горбуша 95 рублей у Петрова"
"обнови треску — 182, Сидоров"
```
LLM-оркестратор разбирает → MemoryAgent сохраняет → подтверждение.

**Б) Пересылка сообщения:**
Поставщик написал в Telegram/WhatsApp → владелец пересылает боту → бот парсит содержимое как свободную фразу.

**В) Команда `/update`:**
```
/update треска б/г 182 Иванов
```

Во всех случаях бот подтверждает: *«Сохранено: треска б/г — 182₽/кг у Иванова. Верно? [✅] [✏️]»*

### 9.7 Fuzzy matching (RapidFuzz)

```python
def normalize_product_name(raw: str, products: list[str]) -> str | None:
    """
    Пример: "ТРЕСКА БГ" → "треска б/г" при score >= 85
    """
    result = process.extractOne(
        raw.lower(),
        [p.lower() for p in products],
        scorer=fuzz.token_sort_ratio,
        score_cutoff=85
    )
    return result[0] if result else None
```

**Если score < 85:** запись сохраняется с `raw_name` заполненным, `product_id = NULL`. Раз в неделю агент спрашивает владельца: «Не смог распознать: "ТРЕСКА ДВ НА ШКУРЕ" — это что?».

## 10. Механизм «обучения» (итеративный)

### Как агент учится писать в стиле владельца

**Шаг 1 — Генерация:**  
ContentAgent генерирует пост по шаблону базового стиля.

**Шаг 2 — Фидбек:**  
После каждого поста автоматически добавляются кнопки:
```
[👍 Хорошо, использовать как пример]  [👎 Переделать]  [✏️ Редактировать]
```

**Шаг 3 — Сохранение:**
- 👍 → `style_examples.feedback_score = 1`, `is_original = false`
- 👎 → бот спрашивает «Что не так?» → ответ сохраняется в `agent_memory["style.corrections"]`
- ✏️ → владелец редактирует текст → итоговый вариант сохраняется с `is_original = true`

**Шаг 4 — Применение:**  
При следующей генерации ContentAgent загружает топ-5 постов с `feedback_score >= 1` как few-shot примеры в системный промпт.

### Как агент помнит бизнес-контекст

Любая новая информация, сказанная владельцу, сохраняется через MemoryAgent:

```
Владелец: "Иванов снижает цены по пятницам"
  → agent_memory["supplier.1.tip"] = "Снижает цены по пятницам"

Владелец: "Марина из Новосибирска берёт только лосось и форель"
  → clients.notes += "Берёт только: лосось, форель"

Владелец: "Не пиши про сроки хранения — клиенты нервничают"
  → agent_memory["style.avoid"] += ["сроки хранения"]
```

7. **fishnet.ru / fishretail.ru структура:** точная разметка HTML изучается при написании парсеров (может измениться).
8. **Имя компании в PDF:** ИП / ООО? Полное юридическое имя для прайса.

## 15. Парсинг 2ГИС — сбор клиентской базы

### Цель

Собрать базу потенциальных клиентов по Владивостоку (и другим городам) через парсинг 2ГИС. Категории: рестораны, кафе, коктейльные бары (HoReCa), рыбные магазины, коптильни, рыбоперерабатывающие цеха.

**Ожидаемый результат:** 1 000–1 500 контактов в CSV/Excel.

### Инструмент

Готовый open-source парсер 2ГИС на Python (GitHub). Запускается локально, не требует серверных ресурсов.

**Репозиторий для исследования:** поискать `2gis parser python` на GitHub — выбрать актуально поддерживаемый.

**Альтернатива:** `2gis-api` — официальный API 2ГИС (бесплатный тариф: 1 000 запросов/день).

### Схема работы

```
Парсер 2ГИС (локально, однократно)
    ↓
CSV-файл: название, категория, адрес, телефон, сайт
    ↓
scripts/import_clients.py — дедупликация + импорт в clients
    ↓
PostgreSQL: clients с type="prospect", is_active=false
    ↓
Бот: команды для работы с базой лидов
```

### Поля для сбора

| Поле | Источник | Комментарий |
|------|---------|-------------|
| name | 2ГИС | Название заведения |
| category | 2ГИС | Ресторан / магазин / коптильня |
| address | 2ГИС | Для определения города |
| phone | 2ГИС | Основной контакт |
| website | 2ГИС | Для дальнейшего поиска Telegram |
| city | Из адреса | Владивосток и другие |

### Схема таблицы `leads` (расширение clients)

Добавить поля в таблицу `clients`:

```sql
ALTER TABLE clients ADD COLUMN source VARCHAR(50) DEFAULT 'manual';
-- source: "2gis", "manual", "referral"

ALTER TABLE clients ADD COLUMN lead_status VARCHAR(30) DEFAULT 'new';
-- lead_status: "new", "contacted", "interested", "converted", "rejected"

ALTER TABLE clients ADD COLUMN address VARCHAR(300);
ALTER TABLE clients ADD COLUMN website VARCHAR(200);
ALTER TABLE clients ADD COLUMN last_contact_at TIMESTAMP;
```

### Команды бота для работы с лидами

| Команда | Описание |
|---------|----------|
| `/import_clients [файл.csv]` | Загрузить базу из CSV в БД |
| `/call_list [город] [категория]` | Список для обзвона (имя + телефон) |
| `/broadcast [шаблон]` | Подготовить рассылку КП по базе |
| `/lead_status [имя] [статус]` | Обновить статус лида после звонка |
| `/stats_leads` | Статистика: новых / обзвонено / конвертировано |

### Пример сценария

```
Владелец: "/call_list Владивосток рестораны"
Бот: "Список для обзвона (47 контактов):
  1. Ресторан Море — +7 423 XXX-XXXX
  2. Кафе Рыбак — +7 924 XXX-XXXX
  ...
  [Экспорт в PDF] [Отметить обзвоненных]"

Владелец: "/broadcast — Отправить КП по всем ресторанам Владивостока"
Бот: "Подготовил рассылку для 47 получателей.
  Текст КП: [предпросмотр]
  Прикреплён прайс: актуальный_прайс_11.11.2026.pdf
  
  Отправить через: [Telegram по одному] [Скопировать список]"
```

### Статус в фазах

- **MVP:** Только `/import_clients` + `/call_list` — загрузить базу и получить список
- **V2:** `/broadcast` — подготовка рассылки с КП
- **V3:** Аналитика конверсии лидов, сегментация по городам

## Приложение A: Почему не fine-tuning

Claude API не поддерживает fine-tuning. Альтернативы:

| Метод | Как реализовано |
|-------|----------------|
| Стиль письма | Few-shot примеры в system prompt ContentAgent (топ-5 из style_examples) |
| Знание бизнеса | PostgreSQL: клиенты, поставщики, цены, история |
| Предпочтения | agent_memory key-value в PostgreSQL |
| Итеративное улучшение | Кнопки 👍/👎 после каждого поста + сохранение фидбека |

Результат идентичен fine-tuning для данного объёма данных.

## Приложение C: Стратегия рассылок

### Принцип: бот готовит, владелец отправляет

Массовая автоматическая рассылка через чужие аккаунты = бан. Поэтому:

| Канал | Как работает | Автоматизация |
|-------|-------------|--------------|
| **Email** | SMTP с твоего email, HTML-шаблон с PDF | ✅ Полная — бот отправляет сам |
| **Telegram** | Список контактов + готовый текст | ⚠️ Полу-авто — ты нажимаешь «Переслать» |
| **WhatsApp** | Только тёплые (кто писал первым) | ⚠️ Полу-авто — список + текст готов |

### Откуда берётся email-база

| Источник | Как собрать | Объём |
|---------|------------|-------|
| Существующие клиенты | clients.csv на старте | 50–100 |
| 2ГИС → сайт организации → email | Парсер сайтов (V1.5) | +300–500 |
| fishnet.ru / fishretail.ru — контакты продавцов | Парсер (MVP) | +100–200 |
| Telegram-каналы — email в описании | Вручную + парсер (V1.5) | +50–100 |

**Итого к V1.5:** ~500–900 email-адресов.

### Email-рассылка: сценарий

```
Владелец: "Разошли прайс по email"
Бот: "Готово к отправке:
  Получателей: 234 (из 312 — активные, у которых есть email)
  Сегменты: рестораны (87), магазины (112), прочие (35)
  
  Тема письма: «Прайс на рыбу и морепродукты — 12.11.2026»
  Текст: [предпросмотр]
  Вложение: прайс_12.11.2026.pdf
  
  [Отправить всем] [Только рестораны] [Редактировать текст]"
```
